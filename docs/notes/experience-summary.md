## 沉淀下来的七条经验

### 1. 先做方案分层，再写代码

面对同一个效果（如 WPO 外扩），先把**全软边副本 / 烘焙平滑法线 / 纯运行时**三条路线摆在一起对比，再选主推方案。烘焙脚本只写额外通道、不改原法线，本体打光就不受影响。方案选错，后面实现再精致也白做。

### 2. 受限环境先探测能力，再设计脚本

UE4.18 的 Content + 预编译 DLL 工程没有引擎源码、也没有 UV 写入 API。做法不是硬猜，而是完整反射扫描 `dir(unreal)`（15142 项、171 个 `*Library` 类），确认能力边界后设计**三层策略**：

| 层 | 策略 | 产出 |
| --- | --- | --- |
| A | 运行时探测自研插件是否暴露写入接口 | 直接写回 3UV/4UV |
| B | 无论 A 是否成功，导出逐 wedge 数据 | JSON + CSV，喂给 DCC / C++ 扩展 |
| C | 导出 `FRawMesh` C++ 写入实现 | 最可靠的无损写回路径 |

这样脚本在任何环境下都有确定产出，不会因为一个 API 缺失而全盘失败。

### 3. 数据通道比算法本身更容易出错

真正耗时的往往不是公式，而是数据在 DCC ↔ 引擎之间传递时的变形：

- FBX 导出会做 `V = 1 - V`，3ds Max 脚本必须**预补偿**，并在 UE 里检查 4UV.v 是否约为 1.0。
- 顶点色可能走 sRGB；UV 存不下 float 时 8bit 顶点色方向误差约 0.2°。
- UE 导入时不要 Recompute Normals；Max 里先 Reset XForm，UE 里保持 Actor 等比缩放。
- 3ds Max 用**角度加权**而非面积加权：模型沿 X 拉伸 3 倍后，面积加权法线明显漂移，角度加权保持不变。

### 4. 尊重平台与版本的约束

- UE4 Custom 节点只能单输出并 `return`，不能定义函数，Input 必须全部接线，否则可能触发 X3004。
- UE4 没有 Additional Outputs，改用 4 个 Custom 节点 + Float3/Float2 通道打包 + ComponentMask 拆分。
- MaterialFunction 必须通过节点调用，不能在 HLSL 里直接调用。
- `return` 类型必须与 Output Type 严格一致。
- 移动端工程统一用 `MF_yaTime` 提供时间，不接引擎原生 Time 节点；目标材质已落地时，通用脚本**勿重复执行覆盖**。

### 5. WPO 的边界要提前说清

WPO 只影响渲染，不改物理碰撞；Nanite 网格忽略 WPO；动态位移要输出 Velocity 防止拖影。骨骼网格的 WPO 在蒙皮前的局部空间生效，不要额外做变换。材质解码法线时只取 `LocalToWorld` 的旋转部分，避免非等比缩放拉歪方向。

### 6. 破坏性操作先备份、先 dry-run

批量改资产前先 p4 备份，只在测试目录验证；首次运行保持 `APPLY_WRITE=False` 做 dry-run。实测手写 ASCII FBX 重导会破坏资产：顶点被重新焊接 524→410、Y 轴翻转、UV0 错乱。因此脚本只产出中间数据，不自动重导。

### 7. 一条链路准备多条落地路径

同一目标（平滑法线）在 Blender / Houdini / 3ds Max / UE4.18 各留一套脚本，并写清各自的假设与验证方法。Blender 配置简单、Houdini 借共享 point 天然得到平均法线、Max 尺度稳定且含实测校验、UE4.18 提供受限工程的兜底方案。工具链的健壮性来自**路径冗余**，而不是单点最优。

## 踩坑速查

| 现象 | 根因 | 应对 |
| --- | --- | --- |
| Custom 节点报 X3004 | Input 未全部接线 | 补齐 13 个引脚，接 ScalarParameter 默认值 |
| 3ds Max 烘的法线在 UE 方向反了 | FBX V 翻转未预补偿 | 写 `V' = 1 - V`，检查 4UV.v ≈ 1.0 |
| 非等比缩放后法线漂移 | 面积加权对尺度敏感 | Reset XForm + 改用角度加权 |
| FBX 重导后网格错乱 | 顶点重焊 / Y 翻转 / UV0 丢失 | 不自动重导，只导出 JSON + CSV 与 C++ 片段 |
| UE4 三阶颜色结果异常 | `return` 类型与 Output Type 不一致 | 严格对齐输出类型 |
| 轮播相位不对 | 用了世界空间相位 | 改为 UV 相位，时间源用 `MF_yaTime` |
